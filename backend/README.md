# Vectorly Backend

The production-grade FastAPI backend for the Retrieval-Aware AI Infrastructure Platform.

## Quick Start (Run Locally in 1 Minute)

From the `backend` directory:

```bash
# 1. Create and activate virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1    # On Linux/macOS: source .venv/bin/activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Apply database migrations
alembic upgrade head

# 4. Start backend server (starts on SQLite vectorly.db out of the box)
uvicorn app.main:app --reload --port 8000
```

- **Health & Readiness Check**: `http://localhost:8000/health`
- **Interactive OpenAPI Documentation**: `http://localhost:8000/docs`
- **API Base URL**: `http://localhost:8000/api/v1`

## Health & Database Readiness Probe

`GET /health` acts as both a liveness and active readiness probe:
- Executes an active `SELECT 1` query against the database connection pool.
- **HTTP 200 OK**:
  ```json
  {
    "status": "ok",
    "database": "connected",
    "environment": "development",
    "version": "0.1.0"
  }
  ```
- **HTTP 503 Service Unavailable** (if the database is unreachable):
  ```json
  {
    "status": "unhealthy",
    "database": "disconnected",
    "error": "Connection to database failed",
    "environment": "production",
    "version": "0.1.0"
  }
  ```

## Database Migrations (Alembic)

Alembic manages database schema migrations, binding to `DATABASE_URL` configured in application settings:

```bash
# Apply all pending migrations to the latest revision
alembic upgrade head

# Roll back one revision
alembic downgrade -1

# Generate a new autogenerated migration from model changes
alembic revision --autogenerate -m "describe changes"
```

## REST API Reference

All protected endpoints require an `Authorization: Bearer <jwt>` header.

### Authentication (`/api/v1/auth`)
- `POST /api/v1/auth/register` — Register a new account (`email`, `password` $\ge 8$ chars, optional `full_name`).
- `POST /api/v1/auth/login` — Sign in and receive signed JWT (`access_token`, `token_type: "bearer"`).
- `GET /api/v1/auth/me` — Return the authenticated user profile.

### Workspaces & Projects (`/api/v1/projects`)
- `POST /api/v1/projects` — Create workspace (automatically derives `owner_id = current_user.id`).
- `GET /api/v1/projects?limit=100&offset=0` — List workspaces owned by current user with pagination.
- `GET /api/v1/projects/{project_id}` — Return project details (scoped to owner).
- `PATCH /api/v1/projects/{project_id}` — Update project name or description.
- `DELETE /api/v1/projects/{project_id}` — Delete project and cascade-delete its documents.

### Documents & Ingestion (`/api/v1/projects/{project_id}/documents`)
- `POST .../upload` — Upload multipart file (`.pdf`, `.md`, `.txt`, `.csv`). Enforces 10MB chunked streaming memory bounds, validates magic byte signatures (`validate_file_content_signature`), extracts text via `pypdf`, and chunks with sentence overlap.
- `POST .../` — Directly index JSON text payload (`name`, `content`, optional `file_type`).
- `GET .../?limit=100&offset=0` — List documents for project with pagination and optional `?status=ready` filter.
- `GET .../{document_id}` — Return document metadata and all its individual indexed chunks.
- `DELETE .../{document_id}` — Cascades and deletes document and its chunks.

### Retrieval & Grounded Synthesis (`/api/v1/projects/{project_id}`)
- `POST .../query` — Hybrid RAG query (`question`, `top_k`, `mode="hybrid"|"bm25"|"semantic"`). Executes BM25 lexical ranking and cosine vector similarity fused through Reciprocal Rank Fusion (RRF $k=60$), then generates grounded synthesis with source citations via the configured LLM provider.
- `POST .../search` — Returns top-K ranked source chunks without LLM synthesis.

### Evaluations & Telemetry (`/api/v1/projects/{project_id}/evaluations`)
- `POST .../` — Record an automated retrieval evaluation benchmark run (`query`, `latency_ms`, `chunks_found`, `mode`, `status`).
- `GET .../?limit=50&offset=0` — List historical evaluation benchmark runs for the workspace with pagination.

## Database Seeder CLI

Vectorly includes an automated database seeder for instant production demo setup:

```bash

python -m app.scripts.seed

# Or wipe and re-seed from scratch

```

## Configuration & Environment Variables

Settings are loaded from `.env` or system environment variables:

```text
# Application Environment (development, staging, production)
APP_ENV=development

# Database Configuration
# Default: Zero-config local SQLite
DATABASE_URL=sqlite:///./vectorly.db
# Production PostgreSQL:
# DATABASE_URL=postgresql+psycopg://postgres:password@localhost:5432/vectorly

# Redis (optional for future queueing/cache)
REDIS_URL=redis://localhost:6379/0

# Pluggable LLM Synthesis Provider (mock, openai, gemini, ollama)
LLM_PROVIDER=mock
LLM_MODEL=local-development
OPENAI_API_KEY=
OPENAI_API_BASE=https://api.openai.com/v1
GEMINI_API_KEY=
OLLAMA_BASE_URL=http://localhost:11434

# Pluggable Dense Neural Embedding Provider (local, openai, gemini, ollama)
EMBEDDING_PROVIDER=local
EMBEDDING_MODEL=local-hash-256
EMBEDDING_DIMENSIONS=256

# JWT Authentication
# IMPORTANT: In production/staging, must be 32+ characters and non-default.
JWT_SECRET_KEY=09d25e094faa6ca2556c818166b7a9563b93f7099f6f0f4caa6cf63b88e8d3e7
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=60

# Reverse Proxy Anti-IP-Spoofing
TRUSTED_PROXIES=127.0.0.1,::1

# Rate Limiting
RATE_LIMIT_ENABLED=true
AUTH_RATE_LIMIT_PER_MINUTE=20
QUERY_RATE_LIMIT_PER_MINUTE=60
GLOBAL_RATE_LIMIT_PER_MINUTE=300

# File Ingestion
MAX_UPLOAD_SIZE_BYTES=10485760
PROMPT_GUARD_ENABLED=true
```

### Production Secret Safety Gating
When `APP_ENV=production` or `APP_ENV=staging`, the application refuses to boot if `JWT_SECRET_KEY` is equal to the development default or is less than 32 characters long.

Build and run the standalone backend container:

```bash
# Run container
docker run -p 8000:8000 --env-file .env vectorly-backend
```
